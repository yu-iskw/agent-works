# Google Docs write negative matrix

This page is the operator negative matrix for GitHub issue 103. The matrix prints deny, hold, and replay rows. It does not grant a scope and does not create a document.

[ADR 0003](../adr/0003-pilot-decisions.md) is Accepted. That record binds the first real write as a Google Docs draft in a shared drive, with no write tool under that record. [RFC-001](../rfcs/RFC-001-Enterprise-Gemini-Style-Agent-Platform.md) is Proposed. The Id, Kind, Result, and When cells match the decision table in the [Write contract](google-docs-write-contract.md). This page adds the Source column. Operators sign this reading before any real write implementation.

Every matching deny or hold contributes to `stop`. A matching `replay` returns the stored receipt and does not post. `post_once` requires an eligible, approved, payload-bound approval with `executionsUsed < maxExecutions`, and matches only when no deny row, no hold row, and no `replay` row matches. Each When cell states whether that row requires an absent receipt.

## Sign-off

A signature on this matrix does not grant a scope, does not create a document, and does not close D-05, D-07, D-11, or D-12. The empty `reviewers` member set in `infra/terraform/environments/dev/tenant.tf` names no approver.

## Shell notes

- The shell persists the idempotency key in the existing claim transaction before the remote call. A concurrent caller that sees the key and no receipt matches `timeout_after_write`.
- If the shell already holds an external operation id, it stores that id as `externalReceipt` and as audit `externalObjectRef`. The next decision matches `replay`. A missing id stays on `timeout_after_write`. No Docs lookup method is named.
