# Google Docs write negative matrix

This page is the operator negative matrix for GitHub issue 103. The matrix prints deny, hold, and replay rows. It does not grant a scope and does not create a document.

[ADR 0003](../adr/0003-pilot-decisions.md) is Accepted. That record binds the first real write as a Google Docs draft in a shared drive, with no write tool under that record. [RFC-001](../rfcs/RFC-001-Enterprise-Gemini-Style-Agent-Platform.md) is Proposed. The row ids are the same ids as the decision table in the [Write contract](google-docs-write-contract.md). Operators sign this reading before any real write implementation.

Every matching deny or hold contributes to `stop`. `replay` returns the stored receipt and does not post. `digest_mutation`, `idempotency_key_mismatch`, and `no_docs_compensation` still apply when a receipt is stored. The other rows apply only when the receipt is absent. `post_once` is unreachable while any hold matches.

## Sign-off

A signature on this matrix does not grant a scope, does not create a document, and does not close D-05, D-07, D-11, or D-12. The empty `reviewers` member set in `infra/terraform/environments/dev/tenant.tf` names no approver.

## Shell notes

- The shell persists the idempotency key before the remote call. A concurrent caller that sees the key and no receipt matches `timeout_after_write`.
- If the shell already holds an external operation id, it stores that id and the next decision matches `replay`. A missing id stays on `timeout_after_write`. No Docs lookup method is named.
