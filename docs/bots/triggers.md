# Bot triggers

The teamwork runtime applies migration 0034 before starting bot triggers. Wire `tick()` to a poller at least once a minute, and pass a source-indexed signing-key resolver from the segment configuration. The raw `handleBotEventRequest` handler belongs before member session authentication. Its request body is JSON encoding of `SignedEvent`, with `body` represented by Node's `{ "type": "Buffer", "data": [...] }` form. The signed `triggerId` is the event type. The handler accepts payloads up to 16 KiB and authenticated events from the previous 300 seconds, including the boundary. Event payloads are untrusted data and do not convey authority.

The scheduler uses the existing scheduling module's UTC slot evaluation in the declared IANA timezone. A local time skipped by spring daylight saving does not fire. A repeated local time in autumn maps to two distinct UTC slots and can fire twice. The existing cron scan looks back at most 366 days. `skip` suppresses slots at least a minute old; `run_once` chooses the latest slot since the cursor. A new revision starts at its publish time. Deferred slots remain pending until the next scheduled slot has passed, after which the capacity miss is audited. Each successful start is deduplicated by its trigger reference.
