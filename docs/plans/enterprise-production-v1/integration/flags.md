# Integration flags

Every flag is read once at startup by `apps/api/src/composition/flags.ts`. Only the exact value `on` enables a capability. Anything else, or no value, leaves it off and the process behaves as before. A flag set to `on` with a missing or malformed required value stops the process with the names (never the values) of what is wrong. In `AW_MODE=production`, `startup/providers.ts` also reports `wiring-config`, `worker-delivery` and `dispatch-queue` for enabled capabilities and rejects a missing, local or non-https endpoint.

## Not wired, with reason

- Scheduler tick still uses its existing claim path. `claimDueWithOutbox` fills the outbox only when the SCH-01 row-claim store is the scheduler owner, which is a separate cutover.
- The standing-authority resolver and grant lifecycle routes need `bindingFor` and `facts` from the teamwork gateway; routine propose/cancel routes need a running-bot identity the API does not yet have.
- Execution worker handler and effect gate (see `AW_EXECUTION_WORKER`).
- `resolveEffect` and `cancelExecution` admin routes.
