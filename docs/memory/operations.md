# Offline operations and validation

## Migration and storage

Use migration `0016_user_memory.sql`. The adapter applies it once per database
using the existing `schema_migrations` convention and a migration advisory lock.
Failed application removes the per-pool readiness cache entry so a retry is
possible. Separate pools serialize memory state writes using lock 7016.

The schema contains these tables:

- `user_memory_consents`: tenant/owner consent and current revision.
- `user_memory_items`: scoped current item, expiry, hold and source-reference index.
- `user_memory_history`: append-only revisioned payloads, cascading erasure.
- `user_memory_audit`: immutable minimal lifecycle events.
- `user_memory_tombstones`: physical-erasure replay evidence.
- `user_memory_revoked_sources`: durable source revocation references.

The adapter reads detached typed state, validates every payload, runs the
operation, checks invariants, and persists within one transaction. No network
ACL calls run under the memory lock. The in-memory adapter uses a FIFO promise
queue and the same invariants, including rollback on callback failure.

The offline state adapter favors clarity and contract parity over large-scale
query efficiency: it loads the local memory state under a shared advisory lock.
A future production query adapter should preserve the same isolation, revision,
consent, hold, deletion, and restore behavior before replacing this driver.

## Retention operation

Call the runtime sweeper from a trusted offline operator schedule. The runtime
reads its trusted clock. Do not supply a browser/model-selected sweep time. A
sweep only physically purges unheld expired content. Recall filters expiry even
if a sweep has not run yet.

Review a legal hold through the existing governance administrative routes. Keep
memory and artifact operations on the same governance port instance. A hold can
target the memory record ID, owner, or cited source reference. Release commands
are append-only governance evidence and are reconciled before the next memory
operation.

## Deletion processing

Register the memory runtime before processing deletion requests. The registration
is scoped to the governance port instance, so independent deployments cannot
silently share a global memory store. Deletion processing waits on memory purge
and accounts for held rows before completing.

A failure during fan-out returns a safe unavailable response. Retry the same
request ID after fixing storage availability. Do not mark a deletion request
complete merely because artifact rows are gone; held memory can keep it HELD.

Current consent and deletion evidence must remain available outside any restored
backup. Apply restore replay before opening traffic. Inspect the replay result
and any legal-hold conflict before continuing a drill. Managed backup evidence
is outside this offline bundle.

## Validation commands

```sh
pnpm install --ignore-scripts
pnpm --filter @agent-works/domain build
pnpm build
pnpm -r exec tsc --noEmit
pnpm exec eslint .
pnpm knip
PATH=/tmp/issue135-bin:$PATH pnpm test
pnpm api:generate
pnpm exec playwright test --config apps/web/app/memory/playwright.config.ts
```

For this task, do not run Trunk. The root `pnpm lint` script delegates to Trunk,
so use direct ESLint and record that substitution explicitly. Apply the requested
Prettier version to changed TypeScript/JSON/Markdown files; the installed core
Prettier has no SQL parser, so inspect SQL separately.

The shared `userMemoryContract` runs against both adapters. The Postgres suite
checks restart durability, audit failure rollback, forbidden history rewrites,
and immutable audit triggers in addition to lifecycle behavior. It requires a
disposable local Postgres/Docker wrapper. If the required wrapper cannot run,
report the skip rather than silently claiming durable storage verification.

The unit suites cover default-off consent, owner/tenant/agent isolation, source
ACL loss and errors, provenance rejection, RESTRICTED refusal, minimization,
revision conflicts, opt-out history erasure, exact TTL boundaries, legal holds,
source revocation, concurrency fences, governance fan-out, restore replay,
runner quoting, route authentication, and CLI safe failures.

Browser smoke and existing HTTP integration tests require permission to bind a
local port. A sandbox `listen EPERM` is an environment limitation; it must be
reported separately from a product assertion failure. Direct handler tests keep
the new management logic executable in that restricted environment.

## Pending integration boundaries

The feature provides its API and web composition roots inside the exclusive
paths, following the existing governance runtime pattern. The root default web
composition stays outside this bundle.
Canonical route fingerprints are regenerated by the explicitly requested
`pnpm api:generate` command. The API and web composition wrappers mount the
feature within the permitted paths. The focused OpenAPI contract lives in
`docs/memory/openapi.json`; adding its operations to the shared generator source
requires a separate path exception.
